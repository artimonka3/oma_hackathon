# Короткий запрос для GitHub Copilot

Отправьте только текст ниже. Документы должны быть доступны в репозитории; вставлять их содержимое в сообщение не нужно.

```text
Организуй задачи проекта artimonka3/oma_hackathon в GitHub Issues и Projects. Выполни реальные действия через доступные API/инструменты. Код продукта не пиши.

Прочитай в репозитории OMA-product-spec.md и docs/technical-spec.md по разделам, не выводя их целиком. Это согласованная спецификация; старый брейншторм не используй. Если файлов нет, сообщи об этом до создания задач.

1. Проверь существующие Issues и Projects. Переиспользуй подходящий Project; если подходящего нет, создай новый у владельца репозитория. При неоднозначности уточни выбор.
2. Разбей реализацию на Epic и небольшие исполняемые Issues. Покрой оба сервиса: Собери, AI/AR, материалы/BOM, Mock OMA и корзину, проверку прорабом перед оплатой, заказ/доставку, отчёты, приёмку, посредничество и общий кабинет.
3. Для каждой задачи укажи цель, конкретные действия, проверяемые критерии готовности, источник в документации, приоритет, роль и зависимости. Тесты включай вместе с поведением, где уместно.
4. Добавь Issues в Project. Поля: Status (Backlog, Ready, In Progress, Review, Done), Priority, Area, Work type, Scope (MVP/Next), Phase. Существующие подходящие поля сохраняй.
5. Создай родительские связи и blocked-by, если инструменты позволяют; иначе добавь ссылки. Проверь отсутствие циклов. В Ready помести только задачи без незакрытых блокеров.
6. Настрой Board, Planning и MVP. Настройка недоступна — точно укажи оставшиеся ручные шаги.
7. Не угадывай исполнителей и даты. Если команда не задана, укажи требуемую роль без Assignee. Не назначай Copilot coding agent.
8. Не создавай дубли. Добавляй стабильный ключ oma-plan в описание задачи. Сохраняй ручные статусы и назначения существующих Issues.

Работай партиями по 5–10 Issues и сохраняй номера созданных задач. Не меняй согласованную архитектуру и не переноси Прораба целиком за пределы MVP.

После выполнения перечитай данные GitHub. Верни ссылку на Project, Epic, первую очередь Ready, зависимости и точные ограничения. Отличай фактически созданное от предложенного.
```
