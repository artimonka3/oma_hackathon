# ОМА.Подбор × ОМА.Прораб

От идеи ремонта до материалов и приёмки работ. Два отдельных сервиса с общими данными проекта:
**Подбор** помогает подобрать отделку и учесть остатки, **Прораб** — найти исполнителя,
проверить комплект и принять выполненную работу.

Go API и адаптивный сайт запускаются вместе. PostgreSQL работает в Docker.
AI подключается через AIHubMix; AR запускает просмотрщик мебели на Android.

## Быстрый старт — Docker

Нужен запущенный Docker Desktop с Docker Compose. Go и Node на компьютере не нужны.

```sh
# Из корня репозитория, один раз. Если .env уже есть, сохраните его.
cp .env.example .env

# Собрать приложение, запустить базу и дождаться готовности.
docker compose up --build -d --wait
```

Открыть **http://127.0.0.1:8088**. Альтернативная команда запуска: `make run`.
Без API-ключа оставьте `AI_MODE=demo`: весь путь работает с подготовленными вариантами.

```sh
docker compose ps                 # состояние app, shop и postgres
docker compose logs -f app        # журнал сервера
docker compose down               # остановить; данные остаются в volumes
```

Повторный запуск после изменения исходников: `docker compose up --build -d --wait`.
После изменения только `.env`: `docker compose up -d --force-recreate app`.

## Что работает

1. **Задача.** Комната и описание желаемых изменений; один проект — одна задача.
2. **Остатки.** Карточки материалов, категории и поиск; можно выбрать несколько позиций,
   задать доступное количество и подтвердить пригодность. Неподтверждённая история
   покупок не уменьшает закупку.
3. **Комната.** Фото по желанию, ручные размеры для расчёта. Отдельная **AR-комната** — инструмент расстановки мебели,
   ожидающий подключения модуля.
4. **Подбор.** Варианты краски, ламината или плитки. В live-режиме их объясняет GLM;
   количество единиц продажи и деньги считает Go.
5. **Корзина.** Учёт совместимых остатков, увеличение количества, самостоятельная покупка
   либо отдельный переход в ОМА.Прораб.
6. **Прораб.** Анализ работ по составу корзины, подходящие профили, выбор специалиста,
   адресная проверка. Изменившийся комплект требует повторного подтверждения.
7. **Заказ.** Неизменяемая котировка, серверная проверка, идемпотентная демооплата и доставка.
8. **Ремонт.** Подтверждение плана, последовательные этапы, фотоотчёты, замечания,
   исправленные версии, явная приёмка заказчиком и завершение проекта.

В шапке можно переключиться между заказчиком и выбранным демо-прорабом.
Отдельные серверные проверки запрещают прорабу принимать собственные работы.

## Текущие границы

- Каталог, цены, профили, оплата и доставка демонстрационные. Деньги не списываются.
- Расчёт основного покрытия: прямоугольная комната, краска в два слоя либо пол/плитка
  с запасом 10%. Проёмы, сложная геометрия, раскладка плитки и полный набор расходников
  пока не учитываются. Это предварительный расчёт, требующий проверки.
- Фото интерьеров — готовые референсы, а не генерация вашей комнаты.
- AR открывает Android-приложение по intent-ссылке; установка приложения нужна на устройстве. См. [AR](docs/AR.md).
- Посредник и сложное двустороннее согласование изменений остаются следующими этапами.
- Общие демо-аккаунты не заменяют регистрацию и вход реальных пользователей.
- Сохранение уже в PostgreSQL, но сервисы пока держат рабочие данные в памяти.
  Поддерживается один экземпляр app; второй блокируется advisory lock базы.

## AIHubMix и GLM-5.3-Flash

В `.env`:

```dotenv
AI_MODE=live
AI_API_KEY=ваш_ключ_AIHubMix
AI_BASE_URL=https://aihubmix.com/v1
AI_MODEL=glm-5.3-flash
AI_TIMEOUT=60s
AI_MAX_TOKENS=4096
```

Ключ хранится только на сервере. Не добавляйте его в `web/`, Git, AR-URL или скриншоты.
`.env` исключён из Git и Docker build context. После настройки пересоздайте app:

```sh
docker compose up -d --force-recreate app
```

Сервер делает один запрос Chat Completions на подбор, передаёт описание задачи,
названия и размеры комнат, подтверждённые остатки и компактный список разрешённых товаров. Фотографии автоматически
в AI не отправляются. Модель возвращает JSON с вариантами и уточнениями. Ответ проверяется:
допустимые SKU, количество вариантов, уникальные ID, длина полей и один основной материал
на вариант. AI не утверждает закупку, не меняет количество и не принимает ремонт.

Для экономии используются короткий контекст, `reasoning_effort=low`, ограничение выхода
и отсутствие автоматических повторов платных запросов. Ошибка ключа, баланса, модели
или JSON видна пользователю; незаметного переключения live-ответа на демо нет.
Возврат к подготовленным решениям: `AI_MODE=demo` и пересоздание app.

`glm-5.3-flash` — выбранная для этого проекта Flash-модель, не утверждение о самом дешёвом
маршруте у всех провайдеров. Доступ и тариф своего ключа проверяйте в AIHubMix.
Бесплатные Coding-маршруты могут иметь отдельные ограничения и не подставляются автоматически.

Подключение проверено локальным HTTP-контрактом и одним живым запросом GLM-5.3-Flash
через AIHubMix 28 октября 2026. При смене ключа доступ проверяйте заново. См. [AI: настройки, ошибки и тесты](docs/AI.md).

## AR — расстановка мебели

На Android появляется кнопка **Открыть AR просмотр**. Она открывает установленное приложение
`com.spatial.arconfig` по ссылке `intent://#Intent;scheme=arconfig;package=com.spatial.arconfig;end`.
На компьютере и iOS показано пояснение о доступности на Android. AR размещает мебель;
размеры комнаты для материалов вводятся вручную. Настройка URL и iframe не требуются.
Подробности в [docs/AR.md](docs/AR.md).

## PostgreSQL и данные

Основная конфигурация Compose:

| Компонент | Настройка |
|---|---|
| PostgreSQL | `postgres:17-alpine`, БД `oma`, пользователь `oma` |
| Порт для локальных SQL-инструментов | `127.0.0.1:54329` |
| Пароль разработки | `POSTGRES_PASSWORD` в `.env`; пример `oma_local_dev` |
| App внутри Docker | `postgres:5432`; строка подключения формируется Compose |
| Постоянные данные | Docker volumes `oma_oma_postgres` и `oma_oma_media` |
| Медиа | `/data/media` в контейнере, отдельный volume |

Это гибридное хранилище: существующие доменные репозитории работают в памяти,
а их согласованный снимок сохраняется в **JSONB-записях PostgreSQL** в одной транзакции.
Это не полностью нормализованные SQL-репозитории. Таблица `oma_components` — источник
восстановления, `oma_runtime` хранит ревизию, `oma_schema_migrations` — версию схемы.
SQL-представления `oma_projects`, `oma_orders`, `oma_reviews`, `oma_reports` позволяют
просматривать отдельные сущности без разбора файла.

Схема автоматически применяется при старте из `internal/checkpoint/schema.sql`.
Старый `migrations/001_init.sql` — исторический черновик нормализованной схемы,
он не применяется текущим запуском. Не запускайте его поверх рабочего хранилища.

```sh
# Открыть SQL-консоль.
docker compose exec postgres psql -U oma -d oma

# Примеры запросов внутри psql:
# SELECT id, goal, version FROM oma_projects;
# SELECT id, status, total_minor FROM oma_orders;
# SELECT revision, updated_at FROM oma_runtime;
```

Все компоненты сохраняются до успешного ответа API. Неудачная SQL-запись откатывает
транзакцию; app прекращает работу, чтобы не отдавать несохранённый кэш. Docker перезапускает
его и восстанавливает последнюю подтверждённую версию. Задания, прерванные в состоянии running,
возвращаются в очередь. Фоновый AI-запрос после аварии может выполниться повторно — это
нужно учитывать при ограничении бюджета ключа.

```sh
# Резервная копия БД в локальный файл. Файл содержит также демо-сессии.
mkdir -p var
docker compose exec -T postgres pg_dump -U oma -d oma > var/oma-backup.sql
```

Не используйте `docker compose down -v`, если хотите сохранить проекты и фотографии.
Для production нужны нормализованные репозитории/команды, реальные сессии,
управление секретами, бэкапы БД **и** media volume, лимиты загрузок и проверка расчётов на реальных данных.

### Перенос прежнего JSON-состояния

Импорт разрешён только в пустую базу и не перезаписывает существующие данные.
Сначала поднимите только PostgreSQL, затем запустите Go-приложение с
`DATABASE_URL`, `OMA_IMPORT_STATE_PATH=./var/mvp-state.json` и свободным `APP_ADDR`.
Убедитесь, что оно стартовало, остановите его и запустите Compose app. Для этого способа нужен Go.
Копию исходного JSON сохраняйте до проверки результата. Старые фотографии переносятся
отдельно вместе с JSON-метаданными из `var/mvp-media/` в media volume; пошагово —
[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md#перенос-медиа).

## Локальная разработка

Нужны Go 1.24+, Python 3 и Docker для базы. Node нужен только для необязательного форматирования.

```sh
make db                  # PostgreSQL в Docker
make run-local           # Go на хосте, читает .env как данные
```

В `.env` значение `DATABASE_URL` для запуска на хосте указывает на `127.0.0.1:54329`,
а не на Docker hostname `postgres`. При изменении пароля синхронизируйте эту строку.
Остановите Compose app перед `make run-local`: база допускает одного писателя.
Необязательный режим без Docker: `make demo`, хранение в `var/mvp-state.json`, AI demo.

## Проверки

```sh
make test
make vet
make smoke
```

`make smoke` использует отдельный сервер, временные файлы и демо-AI; не тратит API-токены.
Проверяет покраску, пол и плитку, остатки, закрытые jobs/медиа, устаревшие подтверждения,
повтор оплаты, доставку, версии отчётов, приёмку, завершение и перезапуск.

SQL-тесты требуют отдельную **одноразовую БД с именем, оканчивающимся на `_test`**:

```sh
TEST_DATABASE_URL='postgres://oma:oma_local_dev@127.0.0.1:54329/oma_store_test?sslmode=disable' go test -race ./...
MVP_TEST_DATABASE_URL='postgres://oma:oma_local_dev@127.0.0.1:54329/oma_e2e_test?sslmode=disable' make smoke
```

Сами базы предварительно создаются через `psql`; основную `oma` для тестов не используйте.
Проверка AI запускается на локальном fake upstream: валидный JSON, неверные SKU,
пустой/невалидный ответ, 401, отсутствие ключа и отсутствие скрытых повторов.

## Будущее API ОМА

Docker Compose автоматически поднимает **shop** из `cmd/mockoma` с каталогом
`oma-site/data/products.json` — 611 товаров из вашего клона. Приложение обращается к нему
по `OMA_API_BASE_URL=http://shop:8090`; витрина доступна по [localhost:8088/shop/](http://127.0.0.1:8088/shop/)
и отдельно [localhost:8090](http://127.0.0.1:8090). Из главного интерфейса можно перейти в каталог.

Товары, цены, фото, корзины, котировки, демо-оплата и доставка проходят через один HTTP API.
Ссылка из корзины подбора открывает эту же корзину в витрине; оформление проектного заказа
возвращает в ОМА.Подбор и сохраняет проверку прорабом. Самостоятельная корзина витрины — отдельное демо.
Цены/остатки взяты из собранного каталога и не гарантируют актуальность на реальном oma.by;
списаний денег нет. Это API вашего клона, а не официальный торговый доступ.

Модель GLM получает до 24 подходящих товаров с реальными SKU, названием, ценой, единицами,
геометрией и остатками пользователя. Сервер проверяет ответ, считает количество и стоимость.
Из рекомендаций исключены неподходящие категории (например, эмали для радиаторов и декоративные ковры)
и товары без данных для расчёта. Килограммы не превращаются в литры; цена за м² остаётся ценой за м².
Расход краски и запас на подрезку предварительные, требуют проверки перед покупкой.

Восемь вымышленных прорабов покрывают покраску, обои, напольные покрытия, плитку и комплексный ремонт.
Кандидаты соответствуют всем типам работ корзины; сначала идут более узкие специализации.
Портреты сгенерированы и обозначены как демонстрационные. [Происхождение изображений](docs/ASSETS.md).

Магазин сохраняет своё состояние в схему PostgreSQL **oma_shop**, приложение — в **public**.
При первом запуске пустой схемы магазин переносит прежний компонент `commerce` из public;
старые проектные корзины и заказы сохраняются. Новые заказы смотрите в `oma_shop.oma_orders`.
Оба процесса используют отдельные advisory locks; масштабирование несколькими писателями не поддерживается.
Для нативного запуска без внешнего API остаётся встроенный тестовый каталог.
Подробнее: [oma-site/README.md](oma-site/README.md), [интеграция магазина](docs/SHOP.md).

## Если что-то не запускается

- **Docker daemon недоступен:** запустите Docker Desktop и дождитесь его готовности.
- **Порт 8088 занят:** остановите прежний Go-стенд или поменяйте `APP_PORT` в `.env`.
- **База занята другим экземпляром:** остановите второй app; advisory lock защищает состояние от перезаписи.
- **Пароль после изменения `.env` не подходит:** PostgreSQL инициализирует пользователя только при первом
  создании volume. Измените пароль SQL-командой; не удаляйте volume с нужными данными.
- **AI live не стартует:** проверьте наличие `AI_API_KEY`, `AI_BASE_URL` и `AI_MODEL`.
- **AI 401/403/429/404:** проверьте ключ, разрешения на модель, квоты и точное имя модели в AIHubMix.
- **AR не запускается:** используйте Android с установленным AR Config и браузер с поддержкой intent-ссылок; см. [AR](docs/AR.md).
