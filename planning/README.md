## Простая доска

Колонки: Backlog → Ready → In Progress → Review → Done. Блок — поле для фильтрации, а не отдельная колонка. Начните с пяти полей: ID, блок, приоритет, исполнитель, зависимости. Scope=MVP/Next отделяет основной путь от дальнейшего развития.

Ready означает достаточные вводные и отсутствие незакрытых обязательных зависимостей. In Progress — есть один ответственный и работа начата. Review — результат доступен для проверки. Done — Критерии выполнены; уместные проверки пройдены; результат проверен другим участником и доступен в целевой ветке/окружении; документация обновлена при необходимости.

Ориентир WIP — одна активная исполняемая задача на человека, при необходимости две. Никто не должен брать десяток параллельных карточек. Epic служит группировкой и не считается отдельной исполняемой задачей.

## Перенос в GitHub Projects

1. Создайте или откройте Project репозитория artimonka3/oma_hackathon. Выберите представление Board и группировку по Status.
2. Создавайте реальные Issues из полных карточек. Сначала перенесите Ready и ближайшие задачи; остальные можно переносить партиями.
3. Добавьте Issues в Project через поле Projects в Issue либо массовое добавление из репозитория.
4. Сохраните ID в названии: [F01] и т. п. В зависимостях используйте реальные URL созданных Issues и по возможности native blocked-by.
5. Назначьте существующих участников команды по ролям. Пустой Assignee лучше случайного назначения.
6. Добавьте представления Ready, MVP и планирование по блокам. Не придумывайте сроки до назначения людей.

CSV является универсальной таблицей данных; возможность его прямого импорта зависит от выбранного сервиса и инструмента. Для GitHub здесь подготовлены содержимое Issues и последовательность их создания, а не обещание встроенного CSV-импорта.

Документация GitHub: [добавление задач](https://docs.github.com/en/issues/planning-and-tracking-with-projects/managing-items-in-your-project/adding-items-to-your-project), [режим Board](https://docs.github.com/en/issues/planning-and-tracking-with-projects/customizing-views-in-your-project/changing-the-layout-of-a-view).

## Работа с Excel

Статус и исполнитель редактируются вручную. Столбцы «Открытых блокеров» и «Следующее действие» пересчитываются по ID и статусам задач, включая после сортировки. Перевод блокера в Done обновляет подсказку, но не меняет статус зависимой задачи автоматически. Next остаётся отдельным развитием. После переноса выберите один основной трекер; CSV, Excel и GitHub не синхронизируются автоматически.

Размеры S/M предварительные. Даты не заданы. «Зависит от» содержит обязательные входные результаты; работа разных направлений может идти параллельно после необходимых контрактов.

## Длинная цепочка технических зависимостей

F01 → F06 → F08 → A01 → A02 → A03 → A04 → C01 → R04 → R05 → R06 → R07 → R08 → Q01 → Q02 → Q04 → E03 → E04 → E05 → D01 → D03 → D02 → T02 → T05 → T06.

Это одна из наиболее длинных цепочек по числу связей. Она не является расчётом критического пути по времени: длительности и доступность людей ещё не оценены. Всего уровней зависимости в MVP: 25. Не нужно переносить эти уровни в календарь как дни.

## Что входит в первую версию

Оба сервиса, несколько помещений, подтверждение имеющегося, расчёт и корзина, адресная проверка до оплаты, симуляция оплаты/доставки, отчёты, замечания, приёмка и посредничество. Next включает OCR, голос, повторные проекты из остатка, передачу материалов, native-сканирование, профессиональный режим, реальную интеграцию ОМА и рыночный пилот.
